# Game System Designer 使用须知

## 适用范围

本 Skill 用于游戏功能需求分析、系统规则、玩家流程、UX/UI 状态、配置差量、策划案、评审、QA 和 Playtest 设计。它不用于纯文案、纯美术创作或未经要求的底层技术实现。

## 安装

以下步骤仅适用于 OpenAI Codex。DeepSeek Harness、Claude、Gemini CLI、Cursor、GitHub Copilot 及其他宿主的目录、调用命令和工具要求，请查看[多 AI 客户端兼容与安装须知](AI-COMPATIBILITY.zh-CN.md)。

### 手动安装

1. 下载或克隆本仓库。
2. 将仓库文件夹复制到 Codex Skill 目录。
3. Windows 默认位置：

   ```text
   %USERPROFILE%\.codex\skills\game-system-designer
   ```

4. 重新打开 Codex 任务，并使用 `$game-system-designer` 调用。

也可以让支持 Skill 安装的 Codex 客户端从本 GitHub 仓库安装。

安装成功只代表客户端能够读取 Skill；能否直接制作 Excel、流程图、UI 图片或读取 Figma，仍取决于当前客户端实际提供的工具。

## 首次使用前必须准备项目素材库

Skill 不自带任何项目的规则、配置、UI 或美术。每个项目第一次使用时都必须提供自己的素材库绝对路径。

建议素材库包含：

- 策划案模板：项目认可的正式策划案与 Excel 模板；
- 配置表：项目真实配置表、字段说明、类型字典和有效示例；
- 项目 UI：已上线或已确认的完整界面截图；
- UI 组件：按钮、页签、框体、图标、状态组件及其变体；
- 项目原画：角色、怪物、场景和活动主题美术；
- 自制 UI：本 Skill 后续产出的版本化完整界面；
- 自制组件：本 Skill 后续产出的可独立复用组件。

目录名称不必完全一致，但内容用途应当明确。切换项目、工作区或素材根目录后需要重新指定，不能沿用其他项目绑定。

## 标准使用流程

1. 指定项目素材库绝对路径。
2. Skill 对需求文档、模板、配置和 UI 素材做只读检查。
3. Skill 将所有会改变玩家结果的问题汇总成一批，一次性提问。
4. 回答后，如出现新矛盾或依赖缺口，Skill 会整理成下一批集中询问。
5. 所有阻断问题解决后，Skill 会汇总完整口径，请你最终确认。
6. 只有确认后才会制作正式策划案、UI、流程图或配置交付。

如果你明确要求“先做待确认草案”，Skill 可以继续，但所有未知项必须明显标记为 `TBD`，且不能伪装成正式结论。

## 推荐调用示例

```text
$game-system-designer 根据这份需求制作功能策划案。
```

```text
$game-system-designer 评审这份策划案，集中列出所有会改变玩家结果的缺口。
```

```text
$game-system-designer 按本项目素材库优化 UI 操作规范，并制作关键状态图。
```

## 重要边界

- 需求文档、竞品截图和旧项目资料只是参考，不自动成为当前项目规则。
- Skill 不会凭经验补造奖励、数值、付费条件、次数、时间或异常处理。
- 配置表里已经支持的通用能力不会为了“显得完整”而重复写进策划案。
- 正文是评审与提测的唯一权威来源；默认不额外建立重复的 UI、流程或验收页签。
- UI 会优先复用项目已有组件和原画；外部参考、生成素材和占位素材必须明确标注来源。
- 源文件和历史版本默认保留，不会在未授权时覆盖或删除。

## 隐私与分发

公开提交需求文档、配置表、UI、原画或策划案前，请确认你拥有分发权限。建议把项目素材库放在私有位置，不要直接提交到这个通用 Skill 仓库。团队需要共享项目资料时，应使用单独的私有仓库或受控存储。

## 能力差异

流程图、Excel、Figma、图片生成或原生应用预览能力取决于使用者安装的 Codex 工具和连接。某项工具不可用时，Skill 应说明限制并提供可验证的替代交付，而不是声称已经完成对应验证。

在其他 AI 中使用时，不要照搬 `$game-system-designer`、Codex 工具名或 Codex 目录。按照[兼容须知](AI-COMPATIBILITY.zh-CN.md)选择对应安装方式；不支持原生 Agent Skills 的客户端，需要手动提供 `SKILL.md` 与本次任务所需的参考文件。
